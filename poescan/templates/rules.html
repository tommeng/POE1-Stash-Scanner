A score is a threshold, not a valuation. These numbers decide one thing: whether an item is worth spending a trade API call on. They are not a prediction of what it sells for, and measured against a real dump tab they were not one — the highest-scoring item in the set (31) was worth 2 chaos, while items scoring 12 ran anywhere from 1 to 25 chaos. What tracked value was scarcity: 5–21 comparable listings meant 20–65c, and 500+ meant 1–2c. So read the table below as what poescan looks at, never as what poescan thinks things are worth. Its whole job is to discard the obvious nothing — about 73% of rares — so the API budget reaches the rest.
Every score here was written by hand. Nothing measured them. All {{ doc.rules|length + doc.veto|length }} are informed guesses about the game, and the repo's own finding that score does not predict price is what unmeasured guesses look like. poescan analyse is the instrument that corrects them, from price observations your own scans already paid for. It judges a rule on its tail — the valuable item it caught — and not on its median, because a filter is judged by what it wrongly discards: of 16 observations worth 50c or more, 12 scored in the lowest band, and the most valuable item in the set (820c) scored exactly the promote score. Treat a big number below as an author's opinion, with a paper trail.

These findings report only what poescan validate-rules structurally cannot see: conditions that are well formed, built from keys the evaluator recognises, and nevertheless dead or always true. Unknown flags, pseudo fields, categories, mod templates, stat ids, base types and broken regexes are that command's job, and it owns the exit code — this one always succeeds, because it is the only tool that renders a broken rule visibly, and dying mid-edit would make it useless.

Vetoes — these run first

A veto discards the item outright, before a single point is scored. That also makes a veto the one rule whose cost cannot be seen: a vetoed item is never priced, so no observation of it exists, and nothing here measures what it threw away. That is the direct corollary of judging a filter by what it wrongly discards.

Each rule carries four numbers or none: how many priced items it fired on, their median, the best one, and how many cleared {{ '%g'|format(evidence.threshold) }}c. The last is the one that matters. Triage is a filter, and a filter is judged by what it wrongly discards, so a rule earns its place by the valuable item it caught and not by its typical one — fractured is the standing example, with a median that says delete it and a tail that says the opposite.
